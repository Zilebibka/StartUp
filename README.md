## Проработка ценностного предложения и функциональности решения  

**Проект:** Маркетплейс незавершённых IT-активов (Dead Code Marketplace)


## Шаг 1. Сегмент и ценностное предложение

### Целевой сегмент

**Покупатели:**
- Малые веб-студии  
- Стартапы  
- Предприниматели (MVP-разработка)  

**Продавцы:**
- Разработчики с незавершёнными проектами  
- Фаундеры закрывшихся стартапов  

---

### Ценностное предложение (операционализированное)

Для малых IT-команд и предпринимателей, которым необходимо быстро запустить MVP с ограниченным бюджетом, платформа предоставляет доступ к проверенным кодовым базам, сокращая срок разработки с 3–4 месяцев до 1–2 недель и снижая затраты до 70% по сравнению с разработкой с нуля, при условии наличия базовой технической экспертизы для интеграции.

---

### Основания доверия

- Автоматизированный AI-аудит кода  
- Готовые архитектурные решения (boilerplate)  
- Безопасная сделка с передачей прав  

---

## Шаг 2. Пользовательские сценарии

### Основной сценарий (покупка)

1. Возникает потребность быстро создать MVP  
2. Пользователь заходит на платформу  
3. Выполняет поиск проекта  
4. Открывает карточку проекта  
5. Изучает AI-аудит  
6. Сравнивает варианты  
7. Оформляет покупку  
8. Получает доступ к коду  
9. Интегрирует в свой проект  
10. Запускает продукт  

---

### Альтернативный сценарий (продажа)

1. Разработчик решает монетизировать проект  
2. Регистрируется на платформе  
3. Загружает код  
4. Проходит AI-аудит  
5. Получает оценку качества  
6. Устанавливает цену  
7. Публикует проект  
8. Получает покупку  
9. Передает права  
10. Получает оплату  

---

## Шаг 4. Backlog MVP

### US1  
Как покупатель, я хочу искать проекты, чтобы быстро находить решения  

Acceptance Criteria:
- Поиск по ключевым словам  
- Наличие фильтров  
- Отображение списка  

Priority: Must  

---

### US2  
Как покупатель, я хочу видеть AI-аудит, чтобы оценить качество  

Acceptance Criteria:
- Отображается оценка  
- Есть описание архитектуры  
- Указан уровень сложности  

Priority: Must  

---

### US3  
Как покупатель, я хочу купить проект  

Acceptance Criteria:
- Есть кнопка покупки  
- Деньги резервируются  
- Доступ после оплаты  

Priority: Must  

---

### US4  
Как продавец, я хочу загрузить проект  

Acceptance Criteria:
- Загрузка репозитория  
- Добавление описания  
- Указание цены  

Priority: Must  

---

### US5  
Как продавец, я хочу пройти аудит  

Acceptance Criteria:
- Запуск анализа  
- Получение отчета  
- Отображение рейтинга  

Priority: Must  

---

### US6  
Как пользователь, я хочу оставить отзыв  

Acceptance Criteria:
- Оценка  
- Комментарий  

Priority: Should  

---

## Шаг 5. Нефункциональные требования

- Безопасность транзакций и данных  
- Время отклика до 2 секунд  
- Доступность системы не ниже 99%  
- Масштабируемость  
- Интеграция с GitHub/GitLab  
- Защита кода  
- Удобный интерфейс  

---

## Шаг 6. Контроль согласованности

- Все шаги сценариев покрыты функциями  
- Все функции ядра обеспечивают ценность  
- Нефункциональные требования соответствуют MVP
